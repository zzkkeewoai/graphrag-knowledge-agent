# 三个 ❌ 的详细说明

## ❌ 1. DOCX 解析缺失

**证据**：全仓库搜 `python-docx` / `from docx`，**零匹配**。

**现状**：支持 `.md`（手写语料）和 `.pdf`（PyMuPDF），不支持 `.docx`。

**为什么这事重要**：企业客户给的制度文件，**docx 比 pdf 更常见**（内部还在编辑的版本就是 docx）。

**修法（20 分钟）**：
```python
from docx import Document
def read_docx(path):
    d = Document(path)
    parts = [p.text for p in d.paragraphs if p.text.strip()]
    for t in d.tables:                     # 表格单独处理，和 PDF 同样的问题
        for row in t.rows:
            parts.append("【表】" + "：".join(c.text.strip() for c in row.cells))
    return "\n".join(parts)
```

**注意**：`d.tables` 必须单独读——**和 PDF 表格丢失是同一个坑**（直接读 paragraphs 拿不到表格内容）。

## ❌ 2. reranker 内部截断（越权）

**证据**：`src/reranker/reranker.py:67-69`

```python
reranked = sorted(documents, key=lambda x: x.get('rerank_score', 0), reverse=True)
return reranked[:top_k]        # ← 在这里就把候选丢了
```

**问题**：reranker 同时承担了"打分"和"选择"两个职责。后果就是你踩过的坑——**截断规则散落在两个地方**（reranker 里 `[:top_k]`、拼 prompt 时又一处），改配置只改一处，效果没变还不知道为什么。

**修法（10 分钟）**：
```python
def rerank(self, query, documents) -> List[Dict]:      # 去掉 top_k
    ...
    return reranked                                     # 只排序，不截断
```
调用方拿完整列表，**截断统一在送 LLM 之前做**。

## ❌ 3. 纯 JSON 不依赖 Neo4j

**证据**：`src/database/neo4j_client.py` 是核心依赖，图谱召回走 Cypher。

**但我不建议改**，理由：

1. **这条和你的项目定位冲突**。你的差异化是「图谱 + 向量混合检索」，去掉 Neo4j 就退化成普通 RAG，**你 10/10 的跨文档多跳成绩直接没了**。
2. **"不依赖外部服务"这个诉求，你已经用另一种方式满足了**——向量库是自己实现的（numpy + json），不依赖 Milvus。这才是当时的真实痛点（Milvus 镜像 403 拉不下来）。
3. **如果面试被问"能不能不装 Neo4j"**，正确答法是讲降级：
   > 「可以。图谱那一路关掉，退化成向量 + BM25，效果会掉但能跑。我在架构上是分层的，`retrieve()` 里三路互相独立，去掉一路不影响另外两路。」

**这条应该标为"与清单约定不符，但属于有意识的设计选择"，不是缺陷。**

# 五个 ⚠️ 的详细说明（按修复优先级）

## ⚠️ A. 两级截断只做了一半（P0，最该修）

**现状**：

| 想要的 | 实际 |
|---|---|
| rerank **前**候选池上限 | ❌ 没有。fused 可能 90+ 条，全量送 rerank |
| rerank **后**按 token 预算裁 | ⚠️ 只有条数（`RERANK_TOP_K`），没有 token 预算 |
| 单 chunk 长度上限 | ⚠️ 有，但**硬编码 1500 字符**（`orchestrator_v2.py:217`），且在 text_map 里而不是独立策略 |

**为什么必须修第一处**：rerank 是无截断的（改完 ❌2 之后），90 条全量编码，**延迟会涨**。候选池上限是**成本保护**，和"相关性过滤"是两件事。

**修法**：
```python
# rerank 前：只保留融合分数最高的 N 条（成本保护，不是相关性判断）
pool = fused[:Config.RERANK_POOL]        # 建议 30
reranked = self.reranker.rerank(query, pool)

# rerank 后：按 token 预算裁，而不是固定条数
selected, used = [], 0
for d in reranked:
    t = count_tokens(d['text'])
    if used + t > Config.CONTEXT_TOKEN_BUDGET:   # 建议 3000
        break
    selected.append(d); used += t
```

**为什么用 token 不用字符**：一条法条 600–900 字、一块 FAQ 只有 50 字，**固定条数的上下文长度方差极大**。

## ⚠️ B. 各环节独立重试（P0）

**现状**：只有 `local_node` 有 `max_retries=3`（`orchestrator_v2.py`），其余环节没有：
- 文档解析：失败即整篇跳过（合理）
- 实体抽取：`ingest_pdf.py:335` 失败只打印，**不重试**——但抽取是 LLM 调用，**网络抖动很常见，这里最该重试**
- 向量入库 / rerank：无重试

**修法**：给抽取加"指数退避 + 3 次"，其余保持"失败即降级"。

**面试价值**：这题答"我按环节区分了'该重试的'和'该放弃的'"比"我统一重试三次"高一个档次。

---

## ⚠️ C. 无文件锁（P0，但影响小）

**现状**：`local_vector_store` 用 `_dirty` 标记"有变更才落盘"，但**没有锁**。入库和查询同时跑，可能出现写到一半被读、或两个进程互相覆盖。

**修法（两条路）**：
- 轻：写文件用 `临时文件 + os.replace`（原子替换），读方永远看到完整文件
- 重：`filelock` 或进程内 `threading.Lock`

**面试怎么说**：「我知道有风险，但我的场景是离线灌库 + 线上查询，**不会并发写**。如果要做双写，我会先上原子替换（`os.replace`），再考虑锁。」

**—— 这个答法比"我加了锁"更真实。**

---

## ⚠️ D. 日志缺 reranker 分数与分步耗时（P0）

**现状**：检索层日志有各路条数、RRF 条数；**reranker 分数没打印**，分步耗时靠 tracer span（不是日志）。

**修法**：在 `rerank()` 后打一行：

```python
logger.info(f"精排: {len(documents)} → {len(reranked)} 条, "
            f"top3 分数={[round(d['rerank_score'],3) for d in reranked[:3]]}")
```

**价值**：这是你诊断"证据被砍"的唯一线索——**当时就是因为我没打这行，才查了半天**。

---

## ⚠️ E. 异常不区分业务/系统（P1）

**现状**：统一 `except Exception`。

**修法**：定义 `BusinessError`（参数不合法、知识库为空）和 `SystemError`（超时、依赖挂），前者不打印堆栈、后者打印。

## 第二批修复（docx + 重试）

| 项 | 实现 | 验证 |
|---|---|---|
| docx 解析 | `extract_docx()`：**按 body 原始顺序**遍历 `w:p` 和 `w:tbl` | 样例 docx dry-run：3 个条款块，表格紧跟"第二条 交通费标准" |
| 抽取重试 | `extract_with_retry()`：3 次，1s→2s→4s；`ingest_simco` 同逻辑 | 假 extractor 失败 2 次→成功（3 次调用 0.31s）；一直失败→返回 `([], TimeoutError)` |

**两个实现细节值得说**：

1. **表格必须按原顺序插回正文**。第一版是先读全部段落、再读全部表格，结果表格被堆到文末，和它所属的条款脱节——"第二条 交通费标准如下"后面跟着的表跑到了最后一行。改成遍历 `doc.element.body` 的 `w:p` / `w:tbl`，顺序就对上了。
2. **解析不重试、抽取才重试**。解析失败基本是文件坏了，重试纯浪费；抽取是网络 + LLM，失败多为限流/超时，隔一两秒成功率很高。**按环节区分"该重试的"和"该放弃的"**，比全局统一重试三次合理。
