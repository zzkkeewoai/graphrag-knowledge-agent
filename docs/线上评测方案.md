# 线上评测方案（设计稿）

> 背景：本项目是自研系统，**没有真实流量**。这份文档写的是"如果上线，我会怎么测"——
> 面试问「你怎么知道线上变好了」，这是唯一能救场的答案。
> 原则：**不写没做过的数据，只写可执行的方案和判据。**

---

## 一、为什么离线评测不够

现有离线评测：`weijin40` + `weijin_hr` = 48 题，100%。

它证明不了三件事：

| 证明不了 | 原因 |
|---|---|
| 真实用户会怎么问 | 题是我按条款写的，用户会问"这个单子能不能批""我们那批货的担保算不算" |
| 检索环境是否稳定 | 线上知识库会更新，离线库是快照 |
| 答对了有没有用 | 答案对 ≠ 用户满意（格式、长度、引用是否可信） |

**离线测"能力"，线上测"效果"。** 两者不能互相替代。

---

## 二、三层评测

```
L1 离线回归    题集固定、可复现、每次改动必跑      —— 防退化
L2 影子比对    真实请求异步双跑，只记录不生效      —— 防线上惊喜
L3 线上指标    分流 + 指标 + 人工抽检              —— 判断真实收益
```

---

## 三、L2 影子流量：怎么切、比什么

### 3.1 切流量

```
用户请求 → 旧版（同步，返回给用户）
         → 新版（异步，超时 30s，只落库，不返回）
```

- **采样率**：先 100% 跑一天（只看差异率，不影响用户），稳定后降到 10%
- **超时与限流**：影子调用必须独立线程池 + 超时，**绝不允许拖慢主请求**
- **存储**：`(request_id, query, old_answer, new_answer, old_route, new_route, 检索命中块, 耗时)`

### 3.2 比什么（按顺序）

| 比对项 | 说明 | 用途 |
|---|---|---|
| **答案差异率** | 两版答案文本相似度 < 阈值 的比例 | 先看"改了多少"，太多说明改动过猛 |
| **拒答差异** | 旧答新拒、旧拒新答 各多少条 | 拒答是最敏感的行为，必须逐条看 |
| **引用差异** | 新版是否给出了条款号 | 新版引用了而旧版没有 → 好信号 |
| **路由差异** | local/global 变化比例 | 路由规则改动的主要风险点 |

**关键动作**：差异样本**人工看 50 条**。影子模式的价值不在指标，在"看到了离线题集里没有的问题类型"。

---

## 四、L3 线上指标

### 4.1 北极星指标

**问题解决率**（一次交互内解决，未追问、未转人工、未重新提问）

```
解决率 = 1 - (追问率 + 转人工率 + 重复提问率)
```

为什么不用"准确率"：线上没有标准答案，无法逐条判对错；而"用户有没有继续问"是**行为信号**，比打分更真实。

### 4.2 质量指标（人工抽检）

| 指标 | 定义 | 目标 |
|---|---|---|
| 抽检准确率 | 每天随机抽 50 条，人工判"答案是否正确且依据充分" | 与离线差距 < 5pp |
| **幻觉率** | 抽检中"答了但知识库没有依据"的比例 | **< 1%，且必须为 0 容忍** |
| 拒答率 | 拒答数 / 总请求 | 观察趋势，突增=检索退化 |
| 引用率 | 答案含条款/文档号的比例 | 越高越好（可溯源） |

### 4.3 性能与成本

| 指标 | 采集方式 |
|---|---|
| P95 / P99 延迟 | 现有 trace 已有 spans |
| 超时率、降级率 | 响应的 `degraded` 字段 |
| 单次成本 | token 用量 × 单价，按天汇总 |
| 缓存命中率 | 语义缓存命中数 / 总请求 |

### 4.4 护栏指标（不能变差）

**任何改动，只要护栏劣化超过阈值就必须回滚，不管北极星涨多少：**

```
幻觉率 +0.5pp 以上        → 回滚
P95 延迟 +30% 以上        → 回滚
超时率翻倍                → 回滚
单次成本 +50% 以上        → 回滚
```

## 五、怎么判断"真的变好了"

### 5.1 分流 A/B

```
用户随机分流 50/50（按 user_id 哈希，保证同一用户体验一致）
持续 1-2 周或累计 N ≥ 1000 请求
```

### 5.2 判据（三条全满足才算好）

1. **北极星显著提升**：解决率差值用两比例检验，p < 0.05
2. **护栏无劣化**：四项护栏都在阈值内
3. **抽检准确率不下降**：人工抽检 200 条，差值在 ±3pp 内

**只满足 1、不满足 2 → 不算成功，是拿质量换指标。**

### 5.3 样本量估算（避免"跑三天就下结论"）

解决率基线约 60%，想检测 +3pp 的提升，α=0.05、power=0.8：

```
每组约需 3,300 条请求
按日均 500 请求 → 约 7 天
```

**这就是"活动周期至少两周"的由来**——不是流程规定，是统计要求。

## 六、离线涨、线上掉：四个原因与对策

| 原因 | 症状 | 对策 |
|---|---|---|
| **分布偏移** | 用户问法与题集差异大（口语、指代、多轮） | 影子模式下聚类真实问题，补进题集 |
| **检索环境漂移** | 知识库更新后旧题仍过 | 评测前先 `ingest` 快照，评测与线上用同一版本号 |
| **评测集泄漏/作者偏见** | 题是我写的，我知道答案长什么样 | 引入第三方出题；题集定期"冷冻"半年 |
| **指标不可比** | 离线判分是规则，线上是行为 | 保持同一判分口径做抽检，别拿两个指标直接比 |

**最容易忽视的是第一条**：我的 48 道题全部是"书面式提问"，而真实用户会说"这批货能不能给担保"——**口语化表达是我完全没测过的**。

---

## 七、上线节奏（灰度 + 回滚）

```
第 1 步  影子跑 3 天        看差异率、人工看 50 条差异样本
第 2 步  灰度 5% 用户 3 天   看护栏指标（幻觉率、延迟、成本）
第 3 步  灰度 50% 用户 1 周  做显著性检验
第 4 步  全量                保留一键回滚开关
```

**回滚条件写死在配置里**，不靠人判断——出事时人是最不可靠的。

---

## 八、数据闭环：Badcase 怎么回到评测集

```
线上点踩/追问/拒答
   → 每周抽取 100 条聚类
   → 挑出题集里没有的问题类型
   → 人工核答案，进"待评估集"
   → 下次改动前先跑，确认不退化
```

**只有这个闭环转起来，题集才不会越用越旧。** 我的 48 题现在是"静态资产"，上线后必须变成"会生长的资产"。

---

## 九、在本项目上的最小可行版（没有流量也能做）

| 步骤 | 做法 | 产出 |
|---|---|---|
| 1 | 用 30 条**口语化改写**替换书面提问（"第十五条说啥"→"担保超净资产一半要谁批"） | 口语集，测分布偏移 |
| 2 | 从历史问答/客服记录（如果有）里抽 50 条真实问法 | 真实分布样本 |
| 3 | 用 `ask_simco.py --trace` 做"回放"：固定问题集，比较两版代码的答案差异 | 简易影子比对 |
| 4 | 每天人工抽检 20 条，记录幻觉率 | 抽检表 |

**第 1 步今天就能做**——把书面题改写成口语题，很可能立刻掉分，那就找到了最真实的短板。

## 十、面试怎么讲这段

> 「我做过离线评测，也想过线上怎么做。三层：离线回归防退化、影子比对防惊喜、线上分流判收益。
>
> 北极星用**问题解决率**而不是准确率——线上没有标准答案，用户有没有继续问是更真实的行为信号。
> 护栏是幻觉率、P95、超时率、单次成本，**任何一项超阈值就回滚，不管北极星涨多少**。
>
> 判据要三条全满足：北极星显著（p<0.05）、护栏无劣化、抽检准确率不降。
> 最担心的背离是**分布偏移**——我的题都是书面式提问，而用户会说'这批货能不能给担保'，这种口语表达我完全没测过。」

**这段话的分量在于：它承认了自己没做过线上，但把方案讲到了可执行的程度。**
