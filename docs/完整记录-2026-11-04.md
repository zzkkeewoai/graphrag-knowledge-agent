# 阶段一：Schema 扩展

## 1. 实体 7 → 13，关系 8 → 13

**为什么**
拿 5 个企业句子试归类，只有「人员」能用。`5万元`「次年3月31日」「二级审批」无处可放，只能塞进「概念」。图里会堆满同类节点，检索无法区分。
只增不改的三个理由：① 枚举值是数据契约，改值要迁移库；② prompt 用 `", ".join(e.value for e in EntityType)` 动态拼，改枚举立刻改变模型行为；③ 旧的项目域 40 题还要当回归基线。

**怎么做** — `src/schemas/graph_schema.py`：

```python
class EntityType(str, Enum):
    # …原有 7 个保持不变…
    CLAUSE = "条款"; THRESHOLD = "阈值"; DEADLINE = "时限"; PROCESS = "流程"
    ROLE = "角色"; ORGANIZATION = "组织"

class RelationType(str, Enum):
    # …原有 8 个保持不变…
    APPROVES = "审批"; APPLIES_TO = "适用于"; EXPIRES_AT = "截止于"
    BASED_ON = "依据"; REPLACES = "替代"
```

**验证**

```powershell

# 13 13
```

## 19. 修拒答判分 → 13/20

**为什么**：模型拒答措辞自由（"信息不足以回答"），只认几个词会把正确拒答判成错——**假阴性会让你去修一个不存在的问题**。

**怎么做** — `run_eval.py`：

```python
REFUSAL_MARKERS = [
    "无法回答","无法确定","无法判断","未找到","未规定","没有规定",
    "未提及","未提供","未涉及","没有相关","没有提到","暂无",
    "不足以","不足够","没有足够",     # 实测中真的出现过
]
def is_refusal(a): return any(m in (a or "") for m in REFUSAL_MARKERS)
# 拒答题单独判：出现任一即算对
```

## 22. 元数据入库 + 拼标题

```

for v in vector_results:

# 五条方法论

1. **噪声会搬家，不会消失。** 删一种错误归因，它会挤进最近的关系类型。要么补类型，要么改产生它的句子。
2. **数字异常先看样本。** 21 条「适用于」看着像 bug，样本一看全合法——差点多加一个没必要的类型。
3. **配置写了不等于生效。** 今天踩了两次。排查手法：改一个参数，看结果有没有变；没变就是没接线。
4. **"答不出来"要分四层定位**：入库 → 召回 → 融合 → 生成。每层都有调试脚本，先看数据再改代码。
5. **判断什么时候停。** 为救 2 道题把向量翻倍，结果撞超时——边际收益递减时收手，把问题记进"已知局限"。

# 阶段九：真实 PDF 接入与规模效应（2026-11-06）

## 49. 为什么必须接真实 PDF

前面所有语料都是**手写 Markdown**——切块天然干净，面试官一句"真实 PDF 你处理过吗"就答不上。而且手写语料会让"95/95"的说服力打折：**内容和格式都是自己造的**。

选了同一家公司（西部黄金）同日发布的 3 份制度：对外担保管理制度（9 页）、股东会议事规则（16 页）、关联交易管理制度（17 页）。

## 50. 解析脚本 `tests/ingest_pdf.py`

四个真实难点，逐个处理：

| 坑 | 现象 | 处理 |
|---|---|---|
| 页脚页码 | `1 / 16` 混进正文 | 整行匹配数字/`数字/数字` 直接删 |
| 中文空格被插入 | `第一章 总 则`，正则匹配失败 | 中文字符之间的空格批量删除 |
| 跨页条款 | 一条制度断成两半 | **先拼后切**：整份 PDF 拼成一条流再按「第X条」切 |
| 无溯源信息 | 命中后不知道出自哪 | 每块前缀 `《文件名》第X章 第Y条：`，元数据记页码 |

结果：**3 份 PDF → 175 个条款块**，页码映射正确（1..9 / 1..16 / 1..17）。

### 写脚本时踩的三个坑（都是"通用代码 + Windows"的典型问题）

1. **文件被处理两遍**：Windows 上 glob 大小写不敏感，`*.pdf` 和 `*.PDF` 同时用会收两遍
2. **标题取了整段**：PDF 里公司名/制度名/副标题常在同一行，取出来是长串且被截断成「…第一章总则第」
3. **条号重复**：「第二条：第二条…」——正文切片从条号开始，前缀又加了一遍

## 51. 致命 bug：每条证据被截断到 200 字

`orchestrator_v2.py` 组装证据时写了 `r.get('text','')[:200]`。

短文档时代完全看不出问题（一块就几十字）。换成 PDF 后，**一条法条普遍 600-900 字，被砍到 200 字只剩半句**，模型只能回答"信息在此处截断，具体比例未完整给出"。

改成 1500 后，回答立刻完整，并且带上了「第三章第十五条」这类条号引用。

**教训**：截断是静默的——它不报错，只让答案变差。条数该由 `RERANK_TOP_K` 控制，单条长度不该再被偷偷砍。

## 52. 规模效应：245 块后为什么掉了一题

灌入后总块数 40 → **245**（175 PDF + 70 原有）。

全量评测：**94/95**，唯一失败的是 `mh08`（员工转岗后权限多久回收，转岗后还能看到合同条款吗）——前半问答对（3 个工作日），后半问答不出。

**根因**：`permissions.md` 那条证据只有几十字，而新增的 175 条法条里全是「合同」「担保」「审批」——**主题一撞，小文档被挤出召回窗口**。这是第一次真实出现的"语料变大导致稀释"，而且掉的正是**依赖两份小文档推理**的题。

### 修复：VECTOR_TOP_K 5 → 8

- `multihop10`：9/10 → **10/10**
- 全量：**95/95**
- 代价：跨文档多跳那组的中位延迟 1836ms → 2024ms（**+10%**）

**这是一次干净的"用延迟换召回"的取舍**，而且有前后数字。

## 53. 阶段性结论

```
245 块（含 175 条真实 PDF 法条）下，105 题仍是 95/95
新增 10% 延迟换回被稀释的召回——这不是拍脑袋调参，是被一题一题逼出来的
```

**待办**：把 simco 自己的 8 篇制度也转成 PDF（含表格），替换 Markdown 版再跑一次——那个才是"同主题稀释"的真测试（现在 PDF 是另一家公司的，和测试题不同域，稀释压力被低估了）。

## 56. 三轮里有两次是判分器错

比"分数波动"更值得注意的是：**5 轮里我修了 3 次判分器假阴性**。

| 模型答的 | 我要求的关键词 | 修法 |
|---|---|---|
| 「百分之**十**」 | `10%` | 中文数字 → 阿拉伯数字 |
| 「**5,000**万元」 | `5000万` | 去掉千分位逗号 |
| 「**无法得知**营业收入」 | 拒答词表里只有「无法回答／无法确定」 | 补 5 个说法 |

三次都是**模型答对了、判分器判错了**。而且第 3 次最阴险：同一道拒答题三次分别说「无法回答」「无法得知」——**措辞会变，判分器跟不上就会把稳定拒答误判成"退化成幻觉"**。

**结论：判分器是评测里最不可靠的组件，比被测系统更容易出错。**

## 57. 唯一不稳定的题：x03

「公司在什么情况下可以暂缓或豁免信息披露？」——5 轮里 2 轮答对、3 轮说"信息不足"。

原因是那条"适用情形"（涉及商业秘密／国家秘密）在召回里时进时出。**这不是能力问题，是检索的边界抖动。**

**处理方式：不调**。这批题已经被看过，再调就是拟合；把它记进基线，等下一批新题再看它是否仍然不稳。

## 58. 阶段性结论

```
纯真实 PDF 语料（338 块）+ 首次出题：18–20/20
波动主要来自判分器假阴性（3 次）与一道题的检索抖动（x03）
```

**这一次最重要的产出不是分数，是"同一套题连跑五轮"这件事本身**——它证明了单次评测的结果不能当结论，而这一点正是很多人做 RAG 项目时缺的。

```

                        ← 路由把它当成"全库汇总"意图
```

**关键词命中歧义**：同一个词在业务语料里是名词/动词的常规用法，在路由规则里却被当成聚合意图。

修法：把「统计」从 global 关键词里删掉（真正的聚合意图由「汇总/概况/整体/所有」覆盖），并在注释里写清原因。

## 62. x03 的真正原因：同文档近义条款互相挤占

「公司在什么情况下可以暂缓或豁免信息披露？」

召回诊断：**同一份《信息披露暂缓豁免制度》里有 11 个块都讲"商业秘密"**，分数全在 0.81–0.84：

```
rank 1  第九条（暂缓后出现情形）      0.837
rank 4  第十一条（暂缓披露临时报告）   0.823
rank 5  第十三条（登记事项）          0.820
rank 6  第七条（适用条件）← 要的是它   0.819
rank 8  第十条（定期报告涉及秘密）     0.811
```

**"适用条件"那条排第 6，被一堆程序性条款挤在后面**，模型拿到的多是"暂缓之后要怎么做"，自然答不出"什么情况下可以暂缓"。

这不是检索坏了，是**同一文档内高度相似的条款互相挤占**。可行的解法是"**条款窗口扩展**"——命中一条后自动带上同文档相邻的 1–2 条，而不是靠提高 top-k 硬塞。

**这一条记进已知局限，本次不修**：题目已被看过，再调就是拟合。

# 阶段十二：加"人事"语料（2026-11-06 下午二）

## 64. 员工手册不存在，改用年报的员工章节

查了 8 类关键词（员工手册 / 人力资源 / 考勤 / 劳动合同 / 职工 / 薪酬 / 招聘 / 培训）+ 手册类（内控手册 / 集体合同 / 职工代表大会），**西部黄金没有公开披露过员工手册**——它属于内部文件，本来就不在披露范围。

同一家公司里最接近"人事实务"的真实文件是**年度报告的"员工情况"章节**：员工人数、专业构成、学历结构、薪酬政策、培训体系、劳务外包。于是从 258 页的 2025 年报里只取第 51–53 页。

## 65. 给解析脚本加 `--pages`

258 页整本灌进去既慢又把无关内容带进检索。新增 `--pages 51-53`，只解析指定页。

配套修了三处：

| 问题 | 现象 | 修法 |
|---|---|---|
| 标题被吃 | `9_2025年年度报告` → `年年度报告` | 只剥 `^\d+[_\-]` 前缀，别把年份也剥了 |
| 小节前内容丢失 | 第一个「一、」之前的内容被丢弃 | 单独切成「前言」块 |
| 页码是"选中页序号" | 显示 p2 而不是 p51 | 记录真实页码列表，按偏移反查 |

## 66. 没有「第X条」的文档要换一种切法

年报、摘要、ESG 报告用的是「七、报告期末员工情况」「(一) 员工情况」这种小节编号，没有条款。原逻辑会切出 **0 块**。

加退化分支：按「一、二、三、」小节切，每块带上小节名。另外小节标题常常在**句号后面**（"…无异议。七、报告期末员工情况"），正则要允许 `[\n。；]` 作为边界。

## 67. 关键发现：PDF 文本提取会把表格数字弄丢

第一版只用 `page.get_text()`，员工表变成：

```
母公司在职员工的数量主要子公司在职员工的数量 / 1,966
在职员工的数量合计 / 2,137 …
```

**母公司的 45 直接没了**；专业构成里的销售 27、技术 462、财务 42、行政 293 **全部丢失**。

修法：用 `page.find_tables()` 单独抽表格，转成「【表】行名：值」的句子补回正文：

```
【表】母公司在职员工的数量：45
【表】主要子公司在职员工的数量：1966
【表】在职员工的数量合计：2137
【表】生产人员：1313 / 销售人员：27 / 技术人员：462 …
```

**踩坑记录**：第一版把表格首行当表头，结果第一行数据被吃掉、值还错列（`45=1966`）。键值表里"标签 + 数字"才是关键，表头名丢了不影响回答——所以改成不猜表头。

## 68. 语料变了，题要跟着变

原来有两道拒答题：

```
r02 公司一共有多少名员工？      → 拒答（制度里没有）
r03 2025年净利润是多少？        → 拒答（制度里没有）
```

加了年报之后，这两道**语料里已经有答案了**（2,137 人 / 471,958,360.67 元）。继续当拒答题就会把"答对了"判成"不该答却答了"。

**改成可答题**，并在 note 里写明原因。**这是评测维护的常规动作：语料变了，题集必须同步，否则测的是旧世界。**

## 69. 路由关键词第二次误判：「一共有多少」

改完题后 r02 又挂了，trace 显示 **route=global**——因为 `global_keywords` 里有「一共有多少」。

但在这个域里，「在职员工一共有多少名」是**查年报里的一个具体数字**，不是"对全库做汇总"。

删掉之后：**40/40**。

两次误判（「统计」「一共有多少」）是同一个病：**规则的词义和业务的词义不一致**。判断标准应该是"这个问题能不能在单条证据里答完"，而不是"句子里有没有某个词"。

weijin40：40/40（单跳 19 · 多跳 13 · 跨文档 6 · 拒答 2）
weijin_hr：8/8（员工数 45 / 1313 / 462 / 553、劳务外包 4078.68 万、培训体系…）
```

# 阶段十三：BM25 混合检索（2026-11-06 下午三）

## 71. 为什么补这一路

向量擅长语义相近，但对**精确术语**不敏感——"第十五条""净资产 50%""每 10 股派息 1.56 元"这种字面唯一的片段，倒排索引往往比 embedding 更准。企业制度/年报里全是这类表述，多份 JD 也明确写"向量 + 倒排混合检索"。

## 72. 实现

`src/retriever/bm25_index.py`：

- **中文用字符二元组切词**（"对外""外担""担保"）：不引 jieba、不会切错专业术语、零维护。
- 索引**直接从本地向量库的块构建**，保证两路看到的是同一批文本。
- `USE_BM25=false` 可关闭，用于 A/B。
- 懒加载：第一次查询时才建索引，不影响启动。

融合：三路（图谱 / 向量 / BM25）进 RRF，并给 BM25 前 2 名做保底（和图谱挤占向量是同一个病）。

## 73. A/B 结果：端到端看不出差别，检索层才看得出来

| 指标 | BM25 关 | BM25 开 |
|---|---|---|
| weijin40 | 40/40 | **40/40** |
| weijin_hr | 8/8 | **8/8** |
| hit@8（检索层） | 46/46 | 46/46 |
| **hit@2** | **45/46** | **46/46** ← 救回 r03 |
| **hit@3** | **45/46** | **46/46** ← 救回 r03 |

**结论要诚实说**：在 344 块、46 道可判分题上，BM25 只救回 1 道（净利润那道）。因为向量在 k=8 时已经能把候选捞全——**加成不明显，成本很低（无额外 LLM 调用），价值在"精确术语"场景的鲁棒性，不是为了刷分。**

这种"加了但收益很小"的结论，比"我加了 BM25 效果显著"可信得多。

## 74. 顺带发现：第四次"配置没接线"

`reciprocal_rank_fusion()` 里写死 `sorted_items[:5]`，而 `Config.FUSION_TOP_K = 8` 从来没被读过。

加了第三路之后这个问题被放大：三路各 8 条竞争 5 个位置，**融合窗口越小越容易把原文挤掉**。改成读配置后，窗口从 5 变 8。

**同一个坑第四次出现**（`RERANK_TOP_K` / `VECTOR_TOP_K` / `docs[:5]` / `FUSION_TOP_K`）。这四个都长得一样：**配置项只出现在 config.py 里，代码里另有一个数字。**

## 75. 另一个度量陷阱

第一版 A/B 脚本统计"候选里有没有关键词"，但 `fused_results` 只留 `doc_id/chunk_index`、**不带 text**。于是它统计的其实是"谁被保底追加了"，得出"开 BM25 后 hit@8 从 46% 掉到 30%"的假结论。

修法：和 orchestrator 一样，用向量/BM25 结果拼 text_map 再回填。**度量脚本本身也会骗人——这是又一次证明。**

## 76. 结果

```

BM25 在窄窗口（k≤3）贡献 +1 题（净利润）
```

# 阶段十四：口语化压测与阈值标定（2026-11-06 下午四）

## 77. 为什么做这一版

前面 48 道题全是**书面式提问**（"单笔担保额超过净资产多少须经股东会审批"），而真实用户会说"我们想给客户做担保，金额有点大，要谁签字"。

这是离线评测最大的洞：**题是我按条款写的，我知道答案长什么样。**

于是把 48 题逐条改写成口语版（`datasets/weijin48_kouyu.jsonl`），语义不变，只改说法。

## 78. 结果：书面 100%，口语 81%

| 版本 | 结果 |
|---|---|
| 书面 48 题 | **48/48 = 100%** |
| **口语 48 题** | **39/48 = 81%** |
| 分类 | 单跳 72% · 多跳 93% · 跨文档 83% · 拒答 100% |

**差 19 个百分点，而且集中在单跳（精确数字题）。**

## 79. 根因不是检索，是拒答阈值

9 道失败里有 7 道回答的是同一句话：「**当前知识库中的信息不足以回答您的问题**」——是证据验证器拒答，不是检索没找到。

验证：

```
"生产线上有多少人"   top1 = 0.475（就是员工情况表）  < 阈值 0.55 → 拒答
"去年净利多少"       top1 = 0.544                  < 阈值 0.55 → 拒答
```

**0.55 这个阈值是在书面语数据上标定的。** 口语与法条的 embedding 分数整体偏低（同一块内容，书面问 0.72，口语问 0.47），所以口语问题被**系统性拒答**。

## 80. 阈值扫描（这才是"阈值怎么定"的正确答案）

| 阈值 | 口语准确率 | 书面准确率 | 无关问题（天气 0.32） |
|---|---|---|---|
| 0.55 | 39/48 = 81% | 48/48 | 拒 ✓ |
| 0.45 | 44/48 = 92% | 48/48 | 拒 ✓ |
| **0.40** | **47/48 = 98%** | **48/48** | **拒 ✓** |
| 0.35 | 未测 | — | （天气 0.32 会漏进来，不能再降） |

**0.40 是最优点**：救回 8 道口语题，书面不退化，且"今天天气"（0.32）与"2026上半年营收"仍被拒。

已写入代码默认值，并把扫描结果写进注释——**换语料或换 embedding 必须重跑这个扫描**。

## 81. 还剩一道真失败

`s10_k`「三方协议要是终止了，多久之内得重新签一份？」——这条确实在《募集资金管理制度》第十二条（两周），但口语问法没把它召回。

**这是检索问题，不是阈值问题**（分数不够，任何阈值都救不了）。记进已知局限。

## 82. 这一步的价值

```
书面 100% → 口语 81% → 调阈值 → 98%
```

**这条曲线比任何单点分数都有说服力**：它说明我知道自己的系统在"换一种问法"时会怎么崩，也知道崩在哪一层（不是检索，是拒答），还知道怎么用数据定位拐点（0.55/0.45/0.40 三点扫描）。

# 阶段十五：多域隔离（2026-11-06 下午五）

## 83. 目标：两套语料共存，一条命令跑全部

之前两套语料（手写 simco、真实 PDF）**只能存在一套**（`--reset` 清库）。目标：共存 + 按域检索不串味。

## 84. 实现：用命名规则推域，零重灌

不额外存元数据（那要重灌全部语料），用确定性的 doc_id 规则推：

```
"1_对外担保管理制度" → pdf        （PDF 都有数字前缀）
"projects"/"people"  → project
其它（org/systems/…） → simco
```

`src/retriever/domain.py` 集中放规则；检索时 `domains=["pdf"]` 只在该域取候选。
有过滤时多取 4 倍候选再截断，避免"取 5 条过滤完只剩 1 条"。

API 接受 `domain` 字段，`run_eval --domain`、`run_all` 按集子声明域。

## 85. 结果：414 块共存，188/191 = 98%

```
语料：PDF 344 + 手写 55 + 项目 15 = 414 块 / 2136 节点
9 套集子 / 201 题 / 9 分钟
```

| 集子 | 结果 |
|---|---|
| 调优集 / 开发集 / 新语料 / 跨文档多跳 | 20/20、20/20、20/20、10/10 |
| 验收集 | 19/20 |
| 原域回归 | 5/5（+10 人工） |
| 真实制度PDF / 年报人事 | 40/40、8/8 |
| 口语版 | 46/48 |
| **合计** | **188/191 = 98%** |

## 86. 关键发现：域过滤没覆盖图谱那一路

`w16`（simco 域）问「公司员工大约有多少人」，期望 1,200（澜海科技），实际答了 **2,137（西部黄金年报）**——**跨域串味**。

原因：我只在向量和 BM25 两路上做了 `keep(doc_id, domains)`，**图谱检索没有过滤**。实体从整张图里查，两套语料的实体本来就混在一张图里（2136 节点）。

**这是"多租户隔离"最典型的坑**：隔离做了一半，等于没做。向量层隔开了，图谱层还是通的。

### 修法（本次未做）

给实体加 `domain` 属性，Cypher 查询时带上 `WHERE n.domain IN $domains`。
需要一次迁移脚本：按 `source_chunk` 所属文件回填每个实体的域。

**这比向量层的过滤更麻烦**——因为同一实体可能出现在多个域（"总经理"既是 simco 的角色，也是 PDF 制度里的角色），要么允许重复节点，要么按 (name, domain) 联合主键。

## 87. 另外两处失败（都是检索 miss，非隔离问题）

- `s10_k`「三方协议终止后多久重签」——第十二条确实有"两周"，口语问法召回不到
- `h05_k`「外包这块一共花了多少钱」——年报有"劳务外包报酬 4,078.68 万元"，同样召回不到

两处都是**口语表述与法条字面差异**导致的召回失败，和之前 `s10_k` 是同一类问题。**阈值救不了，得靠查询改写或关键词扩展。**

# 阶段十六：把图谱层的域隔离补上（2026-11-06 傍晚）

## 88. 修了四层才通

上一阶段只隔离了向量/BM25 两路，图谱那一路还是通的。补的过程连续踩了四个坑，每个坑都表现为"隔离没生效"：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | simco 域仍答出 pdf 的 2,137 人 | 图谱检索没过滤 | 在 `retrieve()` 里过滤 graph_results |
| 2 | 加了过滤仍不过滤 | 图里**没有 source_chunk**，实体无法判域 | 用"实体名出现在哪个域的块文本里"反推 |
| 3 | 反推后 pdf 实体仍漏进来 | 实体名常是拼出来的（"对外担保管理制度第四条"），原文没有这串字 | 加**文档标题兜底**：实体名含某域标题就归该域 |
| 4 | 仍有 pdf 三元组 | 主语常是通用词（"公司"），把证据稀释了 | **取域集合更小的一端**做判据 |
| 5 | 代码全对但结果不变 | **LangGraph 只保留 `AgentState` 里声明过的字段**，`state["domains"]` 被丢掉 | 在 TypedDict 里声明 `domains` |

## 89. 关键判断：三元组级、取更具体的一端

```
"对外担保管理制度第四条 —审批→ 公司"
  主语域 = {pdf}（只在 pdf 出现）
  宾语域 = {pdf, simco}（"公司"两边都有）
```

若取并集会因为"公司也在 simco"而放行——串味就是这么漏的。
**取域集合更小的那个端点**（更具体的那个）才对：这里 {pdf} ⊄ {simco} → 过滤。

## 90. 效果：同一个问题，两个域两个答案

```
POST /ask {"query":"公司员工大约有多少人","domain":"simco"}
  → 公司现有员工约 1200 人            （澜海科技）

POST /ask {"query":"公司员工大约有多少人","domain":"pdf"}
  → 在职员工合计 2,137 人（母公司 45 + 子公司 1,966）（西部黄金年报）
```

**这就是"多租户 / 多知识库隔离"的可验收形态**：同一个问题，按租户给不同答案，且不串味。

## 92. 局限（必须写清楚）

- 实体域是**反推**的近似：实体名恰好出现在别的域文本里会被判跨域。长期方案是**写入时带 domain 属性**（`(name, domain)` 联合主键），需要一次迁移。
- 图谱隔离对"两端都是通用词"的三元组无解（如"公司 —属于→ 组织"），只能放行——**宁可多给，不要误杀**。
